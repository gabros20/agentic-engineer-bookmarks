# CLAUDE.md — project guide

Next.js 16 app for browsing a personal X bookmark archive. It is **private + invite-only**: every page and API route is behind login. Search + AI features are the heart of it.

## Architecture (one screen)
- **Auth-gated (Better Auth + Neon Postgres + invite codes).** Passwordless login (`lib/auth.ts`): one email with a magic link + a 6-digit code (`magicLink` + `emailOTP`, collected into one email by `app/api/login/send` + `lib/sign-in-email.ts`; shared send-gate `mayEmail`), so a sign-in started on a computer (e.g. an MCP client's loopback OAuth) can be finished by typing the code there while the email is read on a phone; invite code only needed for the first sign-in. DB-backed sessions. Account creation is HARD-gated: `databaseHooks.user.create.before` aborts unless an unexpired `pending_signups` row (a redeemed invite code) exists for the email (`lib/invite.ts`). `app/page.tsx` server-checks the session (forged cookie fails it); `proxy.ts` does an optimistic redirect.
- **Search proxies through Vercel, not the browser.** The client POSTs same-origin to **`/api/search`** (`lib/search-client.ts`, zero ML), which checks the session + a per-user daily quota, then forwards to the Cloudflare Worker (`worker/`, `bookmark-search.*.workers.dev`) with a server-only `SEARCH_PROXY_SECRET`. The Worker is **fail-closed** on that secret — the billable Workers-AI pipeline (lunr keyword ⊕ `@cf/baai/bge-m3` semantic ⊕ `@cf/baai/bge-reranker-base` rerank) can't be hit directly. Ranking is byte-identical to the pre-proxy path.
- **Data** = JSON in a **private Cloudflare R2 bucket** (`bookmark-search-data`, T8): the search index (bge `.bin`+`.meta.json`, `lunr-index.json`, `rerank-docs.json`) **and** the raw archive (`all-bookmarks.json`). The Worker reads all of it via its `SEARCH_DATA` R2 binding (cached per isolate). The search index is server-only; the archive is streamed to the logged-in browser through a **session-gated `/api/archive`** → secret-gated Worker `GET /archive` → R2 (the browser's data Web Worker fetches it to render cards). **Nothing is publicly fetchable anymore** — `public/data/*` was removed from git + the Vercel CDN (it stays on disk locally, untracked, for dev/eval via the Worker's `DATA_BASE_URL` fallback). Refresh prod R2 with `npm run upload:r2` (folded into `npm run sync`).
- **AI Digest + ⌘K chat** = Vercel `/api/digest` + `/api/chat`, **session-gated (401 unauth) + per-user daily quota** (`lib/api-guard.ts`: `requireUser` + `enforceQuota`), model `deepseek/deepseek-v4.1-flash-1017` via OpenRouter (`/api/expand` uses `openai/gpt-5.4-nano`). `/api/expand` (query-rewrite) is **session-gated ONLY** — no `enforceQuota` of its own; it's bounded indirectly by the search quota that fronts it. Limits: search 300 / digest 10 / chat 40 per UTC day → 429 (`search_quota`/`digest_quota`/`chat_quota`), surfaced localized in the UI. Digests + chats **persist to Neon**, user-scoped, synced cross-device (the digest tees its `streamObject` and persists in `onFinish`, disconnect-safe). The digest re-queries the Worker for ~50 sources.
- **MCP server** = `app/api/mcp` (Streamable HTTP, `@modelcontextprotocol/server` v2), tools `search_bookmarks` + `get_bookmark` via `lib/server/bookmark-service.ts` (server-side archive cache + the SAME Worker `/search`; shares the **300/day search quota**). Auth = Better Auth 1.7 as OAuth 2.1 server (`jwt()` + `mcp()` + `cimd()` + open DCR in `lib/auth.ts`); `/login` resumes the authorize request (code → directly; magic link → via `/login/continue`, which on a phone shows "Finish on your computer" instead of redirecting to the computer's `localhost`; `/consent` does the same), `/consent` approves; discovery at `app/.well-known/[...path]`. Query filters (operators/content type) are single-sourced in `lib/bookmark-filters.ts` (UI + server). See `docs/MCP-PLAN.md`.
- **Ranking math is single-sourced** in `lib/bookmark-search.ts` + `lib/rerank-core.ts`, reused by the Worker (bundled via `@/` aliases in `worker/wrangler.jsonc`), the proxy path, and the eval harness. Model-specific behavior is **gated on the index `model`/`prefix_scheme`** so the legacy e5 path stays byte-identical.
- **DB schema** (`lib/db/schema.ts`, Drizzle, neon-http — **no interactive txns**, use `db.batch`): Better Auth core (`user`/`session`/`account`/`verification`) + app tables (`invite_codes`, `pending_signups`, `saved_digests`, `chat_sessions`/`chat_messages`, `ai_usage_daily`, `invite_verify_attempts`) + Better Auth OAuth/MCP plugin tables (`jwks`, `oauth*` — faithful to `getAuthTables`, don't rename). Migrations in `drizzle/` via `npm run db:generate` / `db:migrate`.

## Operational rules (don't get burned)
- **Two deploy targets, deploy them TOGETHER.** `git push` → Vercel (app + `/api`; the app no longer serves `/data` — T8 moved it to R2). The **Worker does NOT update on a push** — run **`npm run deploy:worker`** after any Worker/ranking change, and **`npm run upload:r2`** after any *data* change (the Worker reads data from R2, not from a push). Because the live app calls `/api/search` + `/api/archive` with the secret and the Worker is fail-closed on it, the Worker deploy and the app merge must land in the **same window** (see the atomic rollout in `docs/SYNC-AND-DEPLOY.md`): deploying the locked Worker before the app ships would 401 the currently-live search, and merging the app before the Worker is deployed leaves the secret path (and the now-CDN-less `/api/archive`) pointing at nothing. **R2 must be populated (`upload:r2`) before either deploy** — the Worker reads data only from R2 in prod.
- **Env vars (server-only; NO secret in `NEXT_PUBLIC_*`).** `DATABASE_URL` (+ `DATABASE_URL_UNPOOLED` for migrations), `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` (prod origin), `RESEND_API_KEY`, `SEARCH_ENDPOINT` (deployed Worker URL) + `SEARCH_PROXY_SECRET` (also `wrangler secret put` on the Worker), `OPENROUTER_API_KEY`, `DIGEST_UNLOCK_SECRET` (now ONLY the seed invite code — the passkey gate is retired). All must be set in Vercel **before** a build.
- **Sync autopilot (macOS):** launchd agent `com.xbookmarks.sync` ticks `scripts/auto-sync.mjs --scheduled` hourly + at login; `scripts/lib/sync-state.mjs` decides if a run is due (daily from 14:00, same-day retries every 2 h up to 4, missed-day catch-up, offline doesn't burn attempts). Same steps as `npm run sync` + atomic lock, caffeinate, preflights (disk, network, `xrelay whoami`, Cloudflare token via API), weekly xrelay update w/ rollback, truncation guard, publish-when-different-from-last-published, classified failures (`scripts/lib/sync-errors.mjs`) and branded clickable notifications + status page (`scripts/lib/notifier.mjs`, `~/Applications/X Bookmarks Sync.app`). Embedding uses the **Workers AI REST API** with the sync token (`scripts/lib/embed-transport.mjs`; local `wrangler dev` on a free port only as fallback). R2 publish is **versioned** (`v/<hash>/…` + `manifest.json` switched last; the Worker re-checks the manifest each minute, `x-data-version` header). Manage with `npm run autosync -- setup|doctor|status|run|open|logs|notify-test|set-token|set-cookies|install|uninstall`; `npm run test:autosync`. Don't run a manual `npm run sync` concurrently (use `npm run autosync -- run`). **Author threads:** the pull uses `xrelay archive bookmarks --threads` (xrelay ≥ 1.7) and a best-effort backlog step `xrelay archive repair <archive> --threads --limit 300` per run (config `threadBackfillPerRun`); posts carry `thread` (the author's own follow-ups) → detail view thread section + searchable (lunr `thread` field, chunk vectors, rerank excerpt — mirrored in `scripts/lib/search-core.mjs`, drift-guarded).
- **Invite a user:** `node scripts/add-invite.mjs <CODE> [label] [maxUses]` issues an invite code (`npm run add-invite`). The seed code = `DIGEST_UNLOCK_SECRET`.
- **Cloudflare auth is per session; no token is committed** (`worker/.env` deliberately absent). Use `wrangler login` or `export CLOUDFLARE_API_TOKEN=...` before a sync-that-embeds or a deploy. `scripts/sync-bge.mjs` fails fast with instructions if it's missing.
- **Ranking changes are eval-gated:** `npm run eval:bge` (needs a running worker/data server) vs `scripts/eval-baseline-bge.json`; never ship a per-class regression. `npm run test:search` + `npm run test:operators` must stay green.
- **Keep security semantics identical when refactoring the guard/quota/invite code** — limits, 429 codes, and the invite gate are load-bearing.
- **bge-m3 input hygiene** (empty/oversized/lone-surrogate → errors) is handled in `scripts/embed-bge.mjs` — keep it when touching the embed path.
